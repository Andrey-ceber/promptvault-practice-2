# PromptVault — Промпт-библиотека с версиями

Учебное веб-приложение на **Python + SQLite**: сохраняет шаблоны промптов, ведёт неизменяемую историю, сравнивает версии и подставляет переменные. Интерфейс на русском. **Внешних API, вызовов LLM, платных ключей и сгенерированных ответов нет.** Подстановка — обычная обработка текста, а не обращение к модели.

## Исходное задание и принятый scope

В исходном учебном материале указаны название «Промпт-библиотека с версиями», уровень 2/4 и стек Python + SQLite, CLI/веб. **Подробного функционального ТЗ в исходнике нет.** Следующие возможности — явно выбранный авторский scope учебной реализации, а не цитата или реконструкция отсутствующего ТЗ:

- веб-интерфейс; CLI используется для запуска сервера;
- название, описание, теги и исходный шаблон `{{variable}}`;
- создание v1, редактирование → новая версия с обязательным комментарием;
- история защищена от UPDATE/DELETE триггерами SQLite;
- unified diff названия, описания, тегов и шаблона двух версий;
- восстановление старой версии **добавляет новую**, не стирая историю;
- поиск по текущим названию, описанию, тегам и шаблону, без учёта регистра, включая кириллицу;
- текстовый предпросмотр с проверкой отсутствующих/пустых переменных;
- JSON-экспорт всей библиотеки и истории;
- health endpoint, постоянная SQLite, контейнер и CI.

Не входят: аккаунты, совместное редактирование, удаление, импорт JSON, синхронизация, LLM, работа с конфиденциальными данными, промышленное публичное размещение.

## Почему выбран этот проект и стек

Библиотека решает понятную задачу: удачные формулировки легко потерять при правках. История и сравнение показывают практическую ценность версионирования. Уровень 2/4 позволяет пройти полный цикл — данные, доменная логика, веб-формы, тесты, Docker и CI — без усложнения инфраструктурой.

SQLite обеспечивает транзакции и хранение в одном файле; Python включает `sqlite3`, `http.server`, `unittest`, `difflib`, `json`. **Внешних Python-зависимостей нет**, `pip install` не нужен. Простой server-rendered HTML без JavaScript и CDN удобен для проверки XSS и автономного запуска. `http.server` подходит только для локального учебного приложения, не для Интернета.

## Быстрый запуск

Требуется Python 3.12+ (реально проверено на Windows Python 3.14.7 и в Linux-контейнере Python 3.14).

Из корня проекта:

```bash
python -m promptvault --port 8782 --db data/promptvault.db
```

Откройте **http://127.0.0.1:8782**. Остановка — `Ctrl+C`. Повторный запуск с тем же `--db` сохраняет данные. Каталог БД создаётся автоматически. По умолчанию сервер слушает **127.0.0.1**, не всю сеть. `--host 0.0.0.0` предназначен только для контейнера с локальной публикацией порта.

```bash
python -m promptvault --help
python -m unittest discover -s tests -v
python -m compileall -q promptvault tests
```

### Docker Compose

```bash
docker compose build
docker compose run --rm --no-deps app python -m unittest discover -s tests -v
docker compose up -d --wait
# Открыть http://127.0.0.1:8782
docker compose down
```

Порт публикуется только как `127.0.0.1:8782:8782`. SQLite находится в `/data/promptvault.db` в named volume `promptvault-practice2_promptvault_data`, переживающем `down`. **`docker compose down -v` удалит данные** — не используйте для обычной остановки. Процесс контейнера не root; capabilities сняты; настроен healthcheck. Для первого build нужны доступ к Docker Hub и работающий Docker Engine; для локального Python-запуска сеть не нужна.

## Сценарий использования / скринкаста

1. Главная страница: название проекта, поиск и пустое состояние.
2. «+ Новый промпт»: заполнить поля учебным примером:
   - Название: `Учебный план`.
   - Описание: `План самостоятельного изучения темы`.
   - Теги: `учёба, план`.
   - Шаблон: `Составь план изучения темы {{topic}} для {{audience}}. Дай пять шагов.`
   - Комментарий: `Первая формулировка`.
3. Сохранить — карточка с исходным шаблоном и v1.
4. В «Предпросмотр» ввести `{"topic":"История","audience":"начинающих"}`. Показать результат: это подстановка, **не ответ модели**. Попробовать `{}` — понятная ошибка о переменных. Шаблон не меняется.
5. В форме редактирования добавить `Добавь по одному упражнению.` и комментарий `Добавлены упражнения` — появится v2.
6. Выбрать «От версии v1 / К версии v2», нажать «Сравнить версии» — unified diff.
7. Вернуться; восстановить v1 с комментарием `Возврат к короткому варианту` — появится **v3**, v2 останется.
8. Главная → поиск `УЧЁБА`; «Экспорт JSON» → файл с тремя версиями без значений предпросмотра.
9. Материалы для сдачи уже записаны: ссылки на структуру файлов, ввод, результат и скринкаст приведены в разделе «Демонстрация для сдачи».

## Переменные и валидация

- Синтаксис: `{{name}}` или `{{ name }}`; имя `[A-Za-z_][A-Za-z0-9_]*`, регистр важен.
- Повторные переменные подставляются везде. Значения не обрабатываются повторно: `{{other}}` внутри значения остаётся текстом.
- Отсутствующие, нестроковые и пустые обязательные значения отклоняются. Лишние ключи JSON игнорируются.
- Название: 1–120 символов; описание: 0–2000; теги: 0–500; шаблон: 1–20000; комментарий: 1–500. Обязательные поля из пробелов запрещены; NUL запрещён.
- Значение каждой переменной: до 20000 символов. HTTP POST: до 128 КиБ в URL-encoded представлении (кириллица занимает больше байтов); превышение → 413.
- Ошибки ввода → 400; отсутствующая запись/версия → 404; нарушение Host/Origin/CSRF → 403. При ошибке можно вернуться назад в браузере к форме.

## HTTP-маршруты

Приложение в основном отдаёт HTML-формы, это не JSON CRUD API.

| Метод и путь | Назначение |
|---|---|
| `GET /?q=...` | Библиотека и поиск |
| `GET /new` | Форма создания |
| `GET /prompt?id=1` | Шаблон, история, предпросмотр и редактирование |
| `GET /compare?id=1&left=1&right=2` | Unified diff |
| `POST /create` | `title, description, tags, template, comment, csrf` → 303 на карточку |
| `POST /edit?id=1` | Те же поля → новая версия, 303 |
| `POST /restore?id=1` | `version, comment, csrf` → новая версия |
| `POST /render?id=1` | `variables` (строка JSON) и `csrf` → HTML-предпросмотр |
| `GET /export` | JSON-скачивание, `format: promptvault-1`, все версии |
| `GET /health` | `{"status":"ok"}`; проверяется открытие SQLite |
| `GET /static/style.css` | Локальные стили |

POST использует `application/x-www-form-urlencoded`. CSRF-токен берётся из формы текущего процесса сервера; после перезапуска нужно обновить страницу. Разрешены Host `127.0.0.1:порт` / `localhost:порт`. Экспорт не содержит внутреннего пути БД, токенов CSRF и значений предпросмотра.

## Файлы и основные функции

```text
promptvault/
  __init__.py         # пакет, версия
  __main__.py         # main(): аргументы CLI, безопасные defaults, запуск/остановка
  store.py            # Store: транзакции, создание, get/edit/history/restore/search/compare/export
  render.py           # render(): однопроходная подстановка без eval
  web.py              # make_server(), Handler: HTTP-маршруты, формы, HTML-escaping, CSRF
  style.css           # адаптивный русский интерфейс без внешних ресурсов
tests/
  test_store.py       # SQLite, версии, восстановление, триггеры, validation, поиск, diff, экспорт
  test_render.py      # подстановка, обязательные переменные, сохранность исходника
  test_http.py        # реальные TCP/HTTP-запросы, полный поток UI и защита
  test_cli.py         # запуск модуля и help
.github/workflows/ci.yml # unittest + compileall на Windows/Linux, Python 3.12–3.14; Docker-тест
Dockerfile            # Python slim, непривилегированный пользователь, healthcheck
compose.yaml          # локальный порт, постоянный named volume
.gitignore            # БД, кэш, окружение и локальные артефакты не публикуются
.dockerignore         # исключает локальные данные из build context
docs/testing.md       # наблюдавшиеся RED/GREEN и реальные результаты
README.md             # запуск, ограничения, сценарий и архитектура
```

`Store.connect()` закрывает соединение и управляет транзакцией. `edit()` использует `BEGIN IMMEDIATE` и номер `MAX(version)+1`; `restore()` читает старую версию и вызывает `edit()`. `search()` читает текущие версии и применяет Unicode `casefold` в Python: это намеренно простой линейный поиск для небольшой локальной библиотеки. `compare()` сравнивает содержательные поля, не технические timestamps и комментарии.

### Модель данных

`prompts(id)` — идентификатор. `versions(prompt_id, version, title, description, tags, template, comment, created_at)` — полный снимок. Первичный ключ `(prompt_id, version)`, внешний ключ и триггеры защищают целостность. Время хранится в UTC. Снимки, а не дельты, упрощают чтение истории и восстановление.

## Безопасность и ограничения

- Все пользовательские данные экранируются при выводе в HTML; CSP запрещает скрипты, встраивание и внешние ресурсы. SQL-параметры не конкатенируются с вводом.
- CSRF-токен, проверка Host/Origin, `nosniff`, `no-store`, локальный bind по умолчанию. Экспорт читается через GET, поэтому **это не система разграничения доступа**.
- Нет паролей, настоящих API-ключей или корпоративных примеров. Значения предпросмотра не записываются в SQLite и экспорт. Нет запросов во внешнюю сеть при работе приложения.
- **Не вводите секреты в название, описание, теги, шаблон или комментарии.** Экспорт включает все введённые тексты и историю; автоматического распознавания и удаления секретов нет. Перед публикацией JSON проверьте его вручную. Удаление секретов из «текущей» версии не убирает их из истории.
- SQLite-файл доступен владельцу локального компьютера. Администратор файла может обойти триггеры; «неизменяемость» — правило приложения и SQL-триггеров, не криптографическая гарантия.
- Нет авторизации, TLS, защиты от больших нагрузок и полноценного production WSGI/ASGI сервера. Не открывайте порт в Интернет. Для многопользовательского развёртывания нужна отдельная доработка.
- Резервное копирование: остановить сервер и скопировать файл SQLite в безопасное место. JSON здесь — экспорт для просмотра/переноса вручную, автоматического импорта нет.
